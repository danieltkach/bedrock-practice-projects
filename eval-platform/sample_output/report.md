## 8. Method and caveats

- **Quality** of one answer = 50% automatic checks + 50% judge score when a test has both; otherwise whichever exists. Judge scores 1-5 are mapped to 0-1.
- **Judge bias:** LLM judges favour their own style and longer answers. Here the judge is blind to the author, uses a rubric at temperature 0, and a model is not judged by itself when a second judge is configured. A judge that is also a competitor is still a limitation.
- **Latency** depends on load, region and time of day; each call was measured once.
- **Cost** uses estimated list prices and the real token counts returned by the API.
- **Sample size:** a few prompts per category means wide uncertainty (see the quality intervals). Use this as a methodology demo and a first filter, not a final verdict.
- BLEU/ROUGE/BERTScore are not used: they measure overlap with one reference text, which punishes valid paraphrases and suits summarization/translation benchmarks with many references; a rubric judge plus executable checks fits open-ended answers better.
